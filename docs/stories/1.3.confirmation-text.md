# Story 1.3: Confirmation text

## Status

Ready for Review

## Story

**As a patient,**
**I want** a text confirming my appointment,
**so that** I know it is booked and have my visit link.

## Acceptance Criteria

1. Given an imported appointment, then a text goes out within 1 minute of the import.
2. The text holds the clinic name, date, time, professional and visit link, and nothing about the reason for the visit.
3. A re-imported appointment does not get a second confirmation.
4. A failed send appears on the reception screen with the patient's name and the reason, such as an invalid number.

### Completion Notes List

- The text provider is still an open decision (architecture.md › Open decisions). Phase 1 ships the provider interface and a fake that records texts; a real adapter is needed before the pilot.
- Stored message bodies have links and codes redacted. Failed texts are listed on the reception screen with a resend action.
- Jobs use a Postgres job table claimed with SKIP LOCKED (ADR-003) rather than a queue library; dedupe keys stop a second confirmation.
- Tests run against a local Postgres 16 (one database per test file) instead of Testcontainers, because the development container has no Docker.
- All time comes from server/clock.ts; `npm run lint` fails on direct use of the system clock.
